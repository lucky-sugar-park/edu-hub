# FR-04~08 화면 설계명세 — 신청·취소, 내 신청 내역, 관리자 명단·수료

- 상태: **승인됨 (2026-11-19)**. 8절 질문은 모두 제안대로 확정했고 결정 사항 D-31로 기록했다. 구현계획은 `docs/plans/auth-enrollment-ui.md`.
- 대상
  - FR-04~06 화면: 회차 신청, 대기 순번 확인, 취소
  - FR-07 화면: 내 신청 내역
  - FR-08 화면: 관리자 회차 명단과 수료 처리
- 선행: 인증(`NFR-03-auth.md`)과 백엔드 API(FR-04~08, D-19~D-29)
- 규칙: `frontend/CLAUDE.md`(MUI, 생성 클라이언트만, API 인스턴스 한 곳, 화면은 훅으로만, `MemoryRouter` 테스트, 날짜는 `formatDateTime`)
- 브랜치: `feature/auth-enrollment-ui`(인증과 같은 PR)

## 1. 공통

- **API 클라이언트:** 백엔드 변경(인증, 3절의 응답 필드 추가) 후 `npm run generate:api`로 다시 생성한다. `EnrollmentApi`, `EnrollmentAdminApi`, `DevAuthApi`를 `packages/api-client/src/index.ts`에서 내보낸다. `BASE_PATH`는 커밋 전에 8085로 되돌린다.
- **새 훅** (화면은 axios를 모른다)
  - `useMyEnrollments(status, page)`
  - `useEnrollmentActions()`: `enroll`, `cancel`
  - `useSessionRoster(sessionId)`
  - `useCompletion()`
  - 오류는 기존 `toErrorMessage`(백엔드 `ErrorResponse.message`)로 바꾼다.
- **상태 이름:** `statusLabels.ts`에 신청 상태(확정, 대기, 취소, 수료)와 수료 실패 사유(대기 중, 이미 수료, 취소됨, 신청 없음)의 한국어 이름을 더한다.
- **확인 대화 상자:** 취소와 수료는 기존 `ConfirmDialog`로 한 번 더 묻는다. 오류는 대화 상자 안의 `Alert`로 보여 준다(기존 관리 화면 규칙).

## 2. 경로 (D-18 확장)

| 경로 | 화면 | 보호 |
|---|---|---|
| `/` | 과정 목록(기존) | 없음 |
| `/courses/:id` | 과정 상세 + **회차 신청·취소** | 보기는 없음, 신청은 로그인 필요 |
| `/login` | 로그인(인증 설계 4.3) | 없음 |
| `/me/enrollments` | **내 신청 내역** | `RequireAuth` |
| `/admin` | 과정 관리(기존) | `RequireAdmin` |
| `/admin/sessions/:sessionId/roster` | **회차 명단·수료** | `RequireAdmin` |

새 경로(`/login`, `/me/enrollments`, `/admin/sessions/{sessionId}/roster`)는 백엔드 `common/SpaForwardController`에도 추가해 주소를 직접 열 수 있게 한다.

## 3. 백엔드 응답 보완 (화면에 필요한 최소 변경)

| API | 추가 필드 | 이유 |
|---|---|---|
| `GET /api/v1/me/enrollments` (`MyEnrollmentResponse`) | `courseId` | 내 신청 목록에서 과정 상세로 이동하는 링크 |
| `GET /api/v1/admin/sessions/{id}/roster` (`SessionRosterResponse`) | `courseId`, `courseTitle`, `startAt`, `place` | 명단 화면을 주소로 바로 열어도 회차를 알아볼 수 있게 |

- `MyEnrollmentResponse`: FR-07 프로젝션 쿼리에 `c.id`를 더한다. 쿼리 수는 그대로다.
- `SessionRosterResponse`: 회차 조회를 과정까지 한 번에 가져오도록(fetch join 또는 이미 로드된 연관 사용) 해서, 쿼리 수 "회차 1 + 신청 1"을 유지한다.
- 기존 테스트에 필드 단언을 추가한다. OpenAPI 스펙과 생성 클라이언트도 바뀐다.

## 4. FR-04~06 과정 상세의 신청·취소 (`/courses/:id`)

회차 표에 **"내 신청"** 열과 **작업** 열을 더한다.

| 상황 | 내 신청 열 | 작업 |
|---|---|---|
| 비로그인 | - | "로그인 후 신청" 버튼 → `/login`(돌아올 경로 = 이 상세) |
| 신청 없음, 신청 가능 | - | "신청" 버튼 |
| 신청 없음, 신청 불가(회차 종료·시작 후·과정 종료) | - | 버튼 비활성, 사유 툴팁 |
| CONFIRMED | "확정" 칩 | "취소" 버튼(시작 전만 활성) |
| WAITING | "대기 N번" 칩 | "취소" 버튼(시작 전만 활성) |

- **내 신청 상태 조회:** 로그인했으면 `GET /api/v1/me/enrollments?size=100`을 **한 번** 불러, 활성(확정·대기) 신청을 `sessionId`로 매칭한다. 회차마다 따로 부르지 않는다.
  - 한 사원의 신청이 100건을 넘으면 오래된 신청이 빠질 수 있다. 이 화면은 활성 신청만 보므로 실무상 문제는 없다고 보고 한계로 적어 둔다(8절 Q1).
- **신청:** `POST /sessions/{id}/enrollments`를 부른다. 결과는 화면 위 `Alert`로 알린다("신청이 확정되었습니다" 또는 "대기 N번으로 신청되었습니다"). 그 뒤 과정(남은 자리)과 내 신청을 다시 불러온다.
- **취소:** 확인 대화 상자에서 "확정자가 취소하면 대기 1순위가 확정됩니다"를 안내하고, `POST .../me/cancel`을 부른 뒤 다시 불러온다.
- **오류 후 다시 불러오기:** 신청·취소가 실패해도(409, 503 등) 과정과 내 신청을 다시 불러와 서버 상태와 맞춘다. 내 신청을 받아 오기 전이거나 다시 받아 오는 중이거나 실패한 동안은 신청·취소 버튼을 끈다(실패하면 "내 신청 내역을 불러오지 못했습니다"를 알린다).
- **오류:** 409(종료, 시작 후, 중복)와 503(잠시 후 다시 시도)은 백엔드 메시지를 그대로 `Alert`로 보여 준다.
- **활성화 판단:** 회차 상태 `CLOSED`, 시작 시각이 지남, 과정 상태 `CLOSED`면 신청 버튼을 끈다. 최종 판단은 백엔드다(버튼이 켜져 있어도 409를 처리한다).

## 5. FR-07 내 신청 내역 (`/me/enrollments`)

- 상단에 상태 탭: 전체, 확정, 대기, 취소, 수료. 탭은 `status` 파라미터에 대응하고, 바꾸면 첫 페이지로 간다.
- 표의 열
  - 과정(과정 상세 링크)
  - 회차 일시(`formatDateTime`)
  - 장소
  - 상태 칩
  - 대기 순번(대기일 때만)
  - 신청 일시
  - 작업(확정·대기이고 시작 전이면 "취소")
- 페이지는 MUI `TablePagination`이고 20건 단위다(서버 `page`, `size`). 정렬은 서버가 정한 최신순이다.
- 비어 있으면 "신청 내역이 없습니다"와 과정 목록 링크를 보여 준다.
- 취소는 4절과 같은 확인 대화 상자를 쓰고, 성공하면 현재 페이지를 다시 불러온다.

## 6. FR-08 관리자 명단·수료 (`/admin/sessions/:sessionId/roster`)

- **진입:** 과정 관리 화면 회차 표의 작업 열에 "명단" 버튼을 둔다.
- **머리:** 과정 제목, 회차 일시와 장소, 정원, 회차 상태 칩, 확정·수료·대기 수를 따로 표시한다("확정 N명 · 수료 M명 · 대기 K명").
- **확정·수료 표**
  - 열: 체크박스, 사번, 상태(확정·수료), 확정 시각, 수료 시각
  - `CONFIRMED` 행만 선택할 수 있다.
  - 머리 체크박스는 확정자 전체를 선택한다.
  - 선택 상한은 200명이다(백엔드 요청 한도). 머리 체크박스는 아직 선택하지 않은 확정자를 앞에서부터 상한까지만 고르고, 상한에 닿으면 나머지 행은 선택할 수 없다. 확정자가 200명을 넘는 회차에는 안내를 보여 준다.
- **대기 표:** 대기 순번, 사번, 신청 일시(읽기 전용)
- **수료 처리 버튼**
  - 회차가 `CLOSED`이고 선택이 1명 이상일 때만 켠다.
  - 회차가 열려 있으면 "회차를 종료한 뒤 수료 처리할 수 있습니다" 안내를 보여 준다(D-28).
- **결과 대화 상자:** 수료된 사번 목록과 실패한 사번·사유(한국어 이름)를 보여 준다. 닫으면 명단을 다시 불러온다.
- **오류**
  - 409와 503은 메시지를 `Alert`로 보여 준다.
  - 403은 `RequireAdmin`이 먼저 막는다. 토큰의 역할이 바뀐 경우에는 메시지를 표시한다.
  - 404는 "회차를 찾을 수 없습니다"다.

## 7. 테스트 시나리오 (vitest + Testing Library, `MemoryRouter`)

| # | 대상 | 시나리오 |
|---|---|---|
| U1 | 상세 | 비로그인이면 "로그인 후 신청"이 보이고 누르면 `/login`으로 이동 |
| U2 | 상세 | 로그인 상태에서 신청 → API 호출, 확정 또는 대기 N번 알림, 다시 불러오기 |

| U6 | 명단 | 확정·수료·대기 표시, CONFIRMED만 선택 가능, 열린 회차에서 버튼 비활성과 안내 |

| U9 | 훅 | 각 훅의 성공·실패·로딩 상태(기존 훅 테스트 형식) |
