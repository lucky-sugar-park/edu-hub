## T1. 스키마, 엔티티, Repository

**변경 파일**
- 신규 `src/main/resources/db/migration/V4__add_enrollment_cancelled_at.sql`: 설계명세 4.1 그대로(`ALTER TABLE enrollment ADD COLUMN cancelled_at DATETIME(6) NULL;`). V1~V3은 수정하지 않는다.
- `enrollment/EnrollmentStatus.java`: `CANCELLED` 추가
- `enrollment/Enrollment.java`
  - 필드 `cancelledAt`(`Instant`, 컬럼 `cancelled_at`), getter
  - `void cancel(Instant now)`
    - `CONFIRMED`·`WAITING`이 아니면 `IllegalStateException`
    - 상태 `CANCELLED`, `cancelledAt = now`, `waitingKey = null`
    - `confirmedAt`은 그대로 남긴다
  - `void promote(Instant now)`
    - `WAITING`이 아니면 `IllegalStateException`
    - 상태 `CONFIRMED`, `confirmedAt = now`, `waitingKey = null`
- `enrollment/EnrollmentRepository.java`: `List<Enrollment> findBySessionIdAndStatusOrderByWaitingKeyAsc(Long sessionId, EnrollmentStatus status, Pageable pageable)`

**테스트**
- `EnrollmentTest`(E1)
  - 확정 취소: 상태, `cancelledAt`, `confirmedAt` 유지
  - 대기 취소: 키 삭제
  - 이미 취소된 신청을 취소하면 예외
  - 대기 승급: 상태, `confirmedAt`, 키 삭제
  - 확정 상태에서 승급하면 예외
- `EnrollmentRepositoryTest`
  1. `findBy...OrderByWaitingKeyAsc`
     - 음수 키를 포함해 오름차순으로 가져온다
     - 페이지 크기만큼만 가져온다
     - 다른 상태와 다른 회차는 제외한다
  2. 실제 `cancel()`로 취소한 뒤 같은 회차·사번으로 `CONFIRMED`를 다시 저장할 수 있다(D-05, 생성 컬럼 동작)
  3. 취소된 행의 `waiting_key`는 NULL이라 유일 인덱스와 충돌하지 않는다

**완료 명령**
```bash
./gradlew spotlessApply test --tests "*EnrollmentTest" --tests "*EnrollmentRepositoryTest"
```

**검토 포인트**
- V4 무해성(NULL 컬럼 추가)
- 상태 전이의 불변 조건(예외 시 상태 불변)
- `confirmedAt` 처리(취소는 유지, 승급은 갱신)

## T2. 공통 헬퍼 정리와 빈자리 채우기

**변경 파일**
- 신규 `enrollment/WaitingNumbers.java` (패키지 전용 `@Component`)
  - `static final Set<EnrollmentStatus> ACTIVE`
  - `Integer numberOf(Enrollment e)`: 대기면 "같은 회차·더 작은 키 수 + 1", 아니면 null
- `EnrollmentCommandService`, `EnrollmentQueryService`: 중복된 `ACTIVE` 상수와 순번 계산을 `WaitingNumbers`로 바꾼다. **동작 변화 없음.**
- 신규 `enrollment/VacancyFiller.java` (패키지 전용 `@Component`)
  - `int fillVacancies(CourseSession session, Instant now)`
  - 설계명세 2절 그대로다
    - 시작했으면 0
    - 빈자리 = 정원 - 확정 수
    - 빈자리가 있으면 `findBy...OrderByWaitingKeyAsc(WAITING, PageRequest.of(0, 빈자리))`를 각각 `promote(now)`하고 `saveAllAndFlush`
  - 승급한 수를 돌려준다
  - 호출자는 회차 락을 이미 잡은 트랜잭션 안이어야 한다. Javadoc에 적는다.

**테스트**
- 신규 `VacancyFillerTest` (Mockito)
  - 빈자리 2·대기 3 → 앞 2명 승급
  - 빈자리 3·대기 1 → 1명
  - 빈자리 0 → 쿼리·저장 없음
  - 시작 후 → 아무것도 안 함(P3)
  - 승급자 `confirmedAt` = now
- 신규 `WaitingNumbersTest`: 대기 순번, 확정·취소는 null
- 기존 `EnrollmentCommandServiceTest`, `EnrollmentQueryServiceTest`는 생성자만 맞추고 그대로 통과해야 한다(리팩터링 회귀 확인)

**완료 명령**
```bash
./gradlew spotlessApply test --tests "*VacancyFillerTest" --tests "*WaitingNumbersTest" --tests "*EnrollmentCommandServiceTest" --tests "*EnrollmentQueryServiceTest"
```

**검토 포인트**
- 리팩터링이 동작을 바꾸지 않았는지
- 승급 순서(키 오름차순)
- 시작 후 미동작(D-07, D-09)
- 빈자리 계산 경계
