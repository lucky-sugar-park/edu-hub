## 위험 영역

| 위험 | 대응 |
|---|---|
| MariaDB 11.4에서 생성 컬럼 + 유일 제약이 기대대로 동작하지 않음 | T1 테스트 1·3으로 실제 DB에서 확인. 실패하면 구현을 멈추고 보고 |
| `REPEATABLE READ` 스냅숏 때문에 락이 있어도 정원 초과 | `READ_COMMITTED` 지정 + 락 조회를 첫 쿼리로(T3). T5 C1·C2로 확인 |
| `JpaTransactionManager`가 격리 수준 지정을 지원하지 않으면 예외 | Hibernate 방언은 지원한다. T5에서 실제 트랜잭션으로 확인 |
| lock timeout 힌트가 무시되어 기본 50초 대기 | T5에서 관찰. 무시되면 보고하고 `innodb_lock_wait_timeout` 세션 설정을 검토 |
| 락 조회에 fetch join이 들어가 과정 행까지 잠김 | T2 검토 포인트, T5 C4 |
| 동시성 테스트가 `eduhub_test`의 다른 데이터를 지움 | 만든 회차 id로만 정리(T5 검토 포인트) |
| 전체 테스트 실행 시 동시성 테스트가 함께 돌아 시간이 늘어남 | 개발자 확인 후 그대로 둘지, 태그로 분리할지 정한다 |
